# `/cx-peer-loop` 审核闭环

给 Codex 充足上下文，审核一份产物；宿主按评审修改后再送审，直到 Codex 裁决「通过」或触及上限。

产物类型由用户在调用时说明（代码 / 文档 / 计划 / 其它）。未说明则先问一次再开跑。

## 上限

上限与改上限规则见 [records.md](records.md)。观点轮次计入上限；传输重试不计入。

达上限仍未通过：在 `SESSION.md` 写 `达上限` 与未决，交回用户。不要静默加轮。

## 步骤

1. 按 [records.md](records.md) 开 session（`mode=loop`）。记录产物类型、路径、通过标准、上限。
2. 收集上下文写入 `rNN/prompt.md`，必须包括：产物类型与相对路径、通过标准、只读范围、要忽略的脏文件、要求相对路径。输出格式见下。第 2 轮起追加：相对上一轮改了什么、上一轮「必须改」的逐条回应。
3. 按 [cli.md](cli.md) 送审。同一审核闭环复用一个 thread：第 1 轮首轮 exec，其后 `resume`。
4. 成功后把 `-o` 拷到 `rNN/review.md`，填 `rNN/meta.md`，更新 `SESSION.md`。
5. 裁决 `通过`：停。对用户报告路径与轮次。
6. 裁决 `不通过`：宿主按「必须改」修改产物（可写代码/文档）。改完进入下一轮。不要在未改完时送审。
7. Codex 原文没有可解析裁决时：视为本轮失败，短提示 `resume` 要求只补裁决段；仍无则记未决并交回用户，不要猜通过。

## 要求 Codex 使用的输出格式

```markdown
## 摘要
…

## 裁决
- 结果: 通过

## 必须改
（通过时写「无」）

## 边界
…

## 不要做什么
…
```

不通过时 `结果: 不通过`，`必须改` 列出唯一一组修改（不要并列两套等价方案）。

Codex 只审不改。宿主落地修改。
