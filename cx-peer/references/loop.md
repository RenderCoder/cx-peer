# `/cx-peer-loop` 审核闭环

给 Codex 充足上下文，审核一份产物；宿主按评审修改后再送审，直到 Codex 裁决「通过」或触及上限。

产物类型由用户在调用时说明（代码 / 文档 / 计划 / 其它）。未说明则先问一次再开跑。

## 上限

上限与改上限规则见 [records.md](records.md)。观点轮次计入上限；传输重试不计入。

达上限仍未通过：在 `SESSION.md` 写 `达上限` 与未决，交回用户。不要静默加轮。

## 裁决解析

只认唯一一个 `## 裁决` 节里的唯一一行，且该行必须精确为 `- 结果: 通过` 或 `- 结果: 不通过`。

下列都算**无有效裁决**：节缺失、节不唯一、该节内结果行缺失或不唯一、结果行出现在其它章节、文字有偏差。

无有效裁决时：在**当前 `rNN`** 做一次输出修复 attempt（不计观点轮次，每轮最多一次）。提示词要求 Codex **完整重发**评审和裁决，不要只补裁决段。该 attempt 使用独立 `scratch`/`-o` 文件，并写入 `meta.md`。

- 修复 `-o` 同时含有效裁决和完整评审结构（至少 `## 摘要` 与 `## 裁决`）：拷到 `review.md`。
- 修复后仍无有效裁决，或 `-o` 只有裁决没有完整评审：保留原 `review.md`（若有），`SESSION.md` 记 `未决`，停止。不要把只有裁决的短文覆盖完整 `review.md`。不要猜通过。

## 步骤

1. 按 [records.md](records.md) 开 session（`mode=loop`）。记录产物类型、路径、通过标准、实际生效上限。
2. 收集上下文写入 `rNN/prompt.md`，必须包括：产物类型与相对路径、通过标准、只读范围、要忽略的脏文件、要求相对路径。输出格式见下。第 2 轮起追加：相对上一轮改了什么、上一轮「必须改」的逐条回应。
3. 按 [cli.md](cli.md) 送审。同一审核闭环复用一个 thread：第 1 轮首轮 exec，其后 `resume`。
4. 成功后把 `-o` 拷到 `rNN/review.md`，按上一节解析裁决，填 `rNN/meta.md`，更新 `SESSION.md`。
5. 裁决 `通过`：停。对用户报告路径与轮次。
6. 裁决 `不通过`：宿主按「必须改」修改产物（可写代码/文档）。改完进入下一轮。不要在未改完时送审。

## 要求 Codex 使用的输出格式

```markdown
## 摘要
…

## 裁决
- 结果: 通过

## 必须改
（通过时写「无」）

## 边界
…

## 不要做什么
…
```

不通过时 `结果: 不通过`，`必须改` 列出唯一一组修改（不要并列两套等价方案）。

Codex 只审不改。宿主落地修改。
